# 23. Kick: the host removes a guest

Status: Accepted (2026-11-10). Amends 0012 (a host-to-peer `kick` message, `leave` relayed for a
kicked seat), 0016 (seat book, rejoin) and 0017 (waiting room, roster, end copy).

## Context

A host could not get rid of a guest: someone who joined a game by mistake, or who stalls every turn
until the 60 s clock skips it. The host already owns seating (ADR 15), the seat book and its tokens
(ADR 16), and relays `leave {peer}`, which eliminates a team, when a guest quits.

## Decision

- **Who.** Only the host kicks: `Game.kick(seat)` throws on any other page, and a guest accepts a kick
  only from the host (`routeIncoming`), like every other host message.
- **Message.** The host sends the peer `{type: "kick"}`, a targeted send outside the sequence, like
  the seat token. There is no reason and no payload. The peer leaves the room and its game ends with
  "The host removed you from this game." and "Join another game from the lobby." on the end screen,
  above the board when there was a game. The end screen was chosen over going straight to the lobby,
  because every other way a game ends uses it.
- **Waiting room.** Each guest's row in the host's `#room-players` has a **Remove** button
  (`aria-label="Remove abc123"`, the short id). It kicks that peer id and drops it from the list at
  once. The focus moves to the next Remove, or to Add local player.
- **In a game.** The host's roster has a **Kick** button (`aria-label="Kick Team 2"`) for every
  guest's team that is still in; not for the host, bots or local players. After
  `confirm("Kick Team 2? Their team will be out.")`, `kick` revokes the seat in the seat book, sends
  the kick to the peer holding it, and relays `leave {peer: seat}`. That is the existing path for a
  quit: every peer eliminates the team, the turn passes on if it was current, and the replay holds
  it. Every page reads "Team 2 left the game.", since `leave` has no reason; no protocol change was
  needed for the elimination itself. The roster keeps the focus on the button it was on when it is
  rebuilt; when that button is gone (its team was kicked), on the next Kick button, or on the list
  (`#roster`, `tabindex="-1"`). Kicking the current shooter passes the turn on and restarts the clock
  like any `leave` that does (ADR 15), and a bot next in line plays after its usual
  1.5 s minimum (ADR 21).
- **Seat book.** `revoke(seat)` empties the seat's token and holder and remembers the token. So the
  kicked peer's requests no longer count (`seatOf`), the seat is never shown as disconnected, and
  `rejoin` with that token claims nothing. A rejoin with a revoked token is answered with a kick, so a
  tab that kept its seat across a reload ends with the same message instead of waiting forever. A
  kicked page normally has no stored seat anyway, since its game ended.
- **Ignored ids.** The host keeps the kicked peer ids for one hosting, that is one `joinGame`: the
  waiting room and the game that follows it. Their data is dropped, their joins are not reported to
  the page (they never show up in the waiting room again), and each join is answered with another
  kick. The list is in memory only, so it does not survive hosting again, even from the same page and
  room id.
- **Limit.** A Trystero peer id lasts one page load, so a kicked person can reload, get a new id and
  join a public game's waiting room again. The host can remove them again. Keeping someone out for
  good needs a private game (ADR 24) hosted again with a new password or a new link, since the
  kicked person knows the old one.

Rejected:
- A new relayed `kick {peer}` game message: `leave {peer}` already eliminates a team on every peer and
  is valid from the host for any seat. A relayed message also cannot reach a peer in the waiting
  room, which drops everything before `start`.
- Detecting the kick on the kicked page from the `leave` for its own seat: it does not work in the
  waiting room, nor for a peer whose link is down when the `leave` goes out.
- Banning by anything other than the peer id: there is no stable identity (ADR 7, trusted peers).

## Consequences

- One new host-to-peer message, validated at the boundary; the relayed protocol is unchanged.
- A kick is final for that game; there is no undo.
- Tests: `tests/net.test.mjs` (`kick` only from the host, `revoke`/`revoked`), e2e Z (a guest removed
  in the waiting room, who then cannot join again under the same id) and AA (a guest kicked
  mid-game; its reload, even with the old seat token, does not get the seat back) and AE (the
  current shooter kicked with a bot next: the turn passes, the countdown restarts, the bot fires and
  the focus stays in the roster).
